# LocalFlow 포트폴리오 트러블슈팅 기록

이 문서는 포트폴리오 작성용 기록이며 LocalFlow의 프로젝트 분석 및 AI 작업 프롬프트에 포함하지 않는다.

## 복합 프롬프트 분해와 관련 파일 선택 개선

- 기록일: 2026-10-09
- 상태: 구현 및 검증 완료

### 문제

`로컬 로그인 추가 후 JWT 연동`과 같은 복합 요청을 연결어만으로 분해하면 표현에 따라 작업을 놓칠 수 있었다. 또한 파일 경로와 프롬프트 단어만 비교하는 방식은 `SecurityConfig`, 의존성 설정, 사용자 엔티티처럼 이름이 직접 일치하지 않는 관련 파일을 누락할 가능성이 있었다.

Jev는 자유문장을 생성하는 채팅 모델이 아니라 정해진 후보를 선택·평가하는 의사결정 모델이므로, Jev만으로 새로운 작업 문장을 생성하게 하는 방식도 역할에 맞지 않았다.

### 검토했던 방식

1. 로컬 연결어 규칙만으로 프롬프트 분해
2. 로컬에서 작업을 확정하고 Jev는 태그만 선택
3. 생성형 AI가 의미 기반으로 작업을 분해하고 Jev가 이를 검증

### 최종 결정

다음 파이프라인을 사용한다.

```text
사용자가 선택한 생성 AI 호출
→ 원본 프롬프트를 작업 단위와 의존 관계로 분해
→ Jev 호출
→ 작업 유효성, 관련 태그, 위험도, 승인 필요 여부 판단
→ 태그 기반으로 작업별 관련 파일 조회
→ 선택한 생성 AI를 다시 호출하여 통합 변경 계획 생성
→ 변경 전후 미리보기 및 사용자 승인
→ 업로드된 프로젝트 사본에 적용하고 결과 반환
```

생성 AI는 의미 이해와 작업 설계를 담당하고, Jev는 생성된 작업을 정형적으로 검증하며, 두 번째 생성 AI 호출은 확정된 작업과 관련 파일을 기반으로 실제 코드를 작성한다.

MVP에서는 작업마다 파일을 즉시 수정하지 않고 모든 작업을 하나의 통합 변경 계획으로 만든 뒤 한 번에 승인한다. 이를 통해 단계별 호출 중 일부 파일만 변경된 상태로 남는 문제를 줄인다.

### 실패 대비

- 작업 분해 AI 호출 또는 JSON 파싱 실패: 기존 로컬 규칙 기반 분해 사용
- Jev 호출 실패: 생성 AI 제안 태그와 로컬 태그 규칙 사용
- 실행 AI 호출 또는 계획 검증 실패: 파일을 적용하지 않고 실패 기록 저장
- 낮은 판단 신뢰도: 자동 적용하지 않고 사용자 승인 요구

### 트레이드오프

- 생성 AI를 분해와 실행에 각각 호출하므로 호출 비용과 지연 시간이 증가한다.
- 대신 복합 요청의 의미 기반 분해, 관련 파일 검색 정확도, 작업 과정의 설명 가능성이 향상된다.
- 로컬 규칙을 대체 경로로 유지하여 외부 API 장애나 로컬 전용 환경에서도 실행할 수 있다.

### 구현 결과

- 선택한 OpenAI, Vertex AI 또는 Ollama를 첫 번째로 호출해 최대 5개 작업과 의존 관계, 제안 태그, 완료 조건을 구조화한다.
- Jev가 작업별 유효성과 관련 태그, 전체 위험도와 승인 필요 여부를 판단한다.
- 태그 기반으로 작업별 관련 파일을 선정한 뒤 같은 생성 AI를 다시 호출해 하나의 통합 변경 계획을 만든다.
- 작업 분해 JSON을 실행 기록에 별도로 저장하고 화면에서 분해 출처, 선행 작업, 태그와 완료 조건을 확인할 수 있다.
- 분해 호출 또는 JSON 파싱 실패 시 로컬 규칙 기반 분해로 자동 전환한다.
- 백엔드 회귀 테스트와 프론트엔드 프로덕션 빌드로 변경 사항을 검증했다.

### 포트폴리오 핵심 요약

규칙 기반 분해의 표현 의존성과 경로 기반 파일 검색의 누락 문제를 발견했다. 생성형 AI의 의미 분석 능력과 Jev의 정형 판단 능력을 분리해 `AI 작업 분해 → Jev 검증·태그 선택 → AI 통합 실행` 파이프라인으로 재설계했으며, 실패 시 로컬 규칙으로 복구하도록 구성했다.
